好。下面正式进入 **《AI会议室智能巡检系统 V1.0——数据库详细设计》**。

这一版我会按照“**可以直接交给开发人员建库**”的标准设计，而不是只做概念模型。

# 1. V1.0数据库设计目标

本系统数据库需要解决 6 件事情：

1. 管理公司有哪些会议室
2. 管理每个会议室有哪些巡检指标
3. 管理标准照片以及照片中的识别区域
4. 自动生成每天早/中/晚巡检任务
5. 保存现场照片和AI识别结果
6. 保存人工确认后的最终结果

核心关系：

```text
会议室
   │
   ├──────── 标准照片
   │              │
   │              └── 照片区域
   │                       │
   │                       └── 巡检指标
   │
   └──────── 会议室巡检指标
                    │
                    ↓
              巡检任务
                    │
             ┌──────┴──────┐
             ↓             ↓
         现场照片       巡检结果
                           │
                      AI结果
                           │
                      人工确认
                           │
                      最终结果
```

## 5.1 I001 灯

```text
正常条件：

异常条件：

```

## 5.2 I002 空调

```text
正常条件：
空调处于关闭状态，未发现运行指示。

异常条件：
```

## 5.3 I003 电脑显示器

```text
正常条件：

异常条件：
显示器处于明显亮屏状态。
```

> **“显示器状态”**

```text
       ↓

       ↓
```

而：

```text

       ↓

       ↓

```

形成：

```text
会议室
 ↓
标准照片
 ↓
区域
 ↓

```

这正是我们需要的关系。

# 9. 标准照片版本机制

这个设计非常重要。

假设：

2026年：

```text
301会议室
标准照片V1
```

后来会议室重新装修：

```text
桌子换了
投影仪换了
椅子换了
```

不能直接覆盖历史标准照片。

应该：

```text
V1
 ↓
ARCHIVED

V2
 ↓
ACTIVE
```

这样历史巡检记录仍然可以追溯。

# 11. 为什么使用0～1坐标？

假设原图：

```text
1920 × 1080
```

桌面区域：

```text
x = 0.35
y = 0.55
width = 0.40
height = 0.30
```

实际像素：

```text
x = 672
y = 594
width = 768
height = 324
```

以后图片变成：

```text
1280 × 720
```

仍然可以计算。

所以不要把：

```text
672,594,768,324
```

直接写进数据库。

# 12. 一个区域可以对应多个指标

例如：

```text
桌面区域
```

可能同时关联：

```text
电脑
桌面整洁
键盘
电话
```

因此不要在 `photo_region` 里直接写死一个 indicator。

后续可以进一步增加：

```text
region_indicator
```

表。

不过V1.0如果一个区域只对应一个指标，可以暂时简化。

# 14. 任务状态

不要只用：

```text
完成/未完成
```

建议：

```text
PENDING
    ↓
IN_PROGRESS
    ↓
AI_ANALYZING
    ↓
WAITING_CONFIRM
    ↓
COMPLETED
```

异常情况：

```text
CANCELLED
EXPIRED
RETAKE_REQUIRED
```

完整状态机：

```text
PENDING
   │
   ▼
IN_PROGRESS
   │
   ▼
AI_ANALYZING
   │
   ▼
WAITING_CONFIRM
   │
   ├──────────────┐
   ▼              ▼
COMPLETED     RETAKE_REQUIRED
                  │
                  ▼
             IN_PROGRESS
```

# 19. 最终状态怎么产生？

例如：

```text
AI：
ABNORMAL
confidence = 0.94

人工：
NORMAL

最终：
NORMAL
```

即：

> **人工确认拥有最高优先级。**

系统必须保留AI原始判断，不能覆盖。

# 20. ai_bbox怎么存？

PostgreSQL使用：

```text
JSONB
```

例如：

```json
{
  "x": 0.42,
  "y": 0.61,
  "width": 0.32,
  "height": 0.18
}
```

也可以：

```json
{
  "boxes": [
    {
      "x": 0.42,
      "y": 0.61,
      "width": 0.32,
      "height": 0.18
    }
  ]
}
```

未来可以支持一个指标多个异常区域。

# 22. PostgreSQL建表SQL

下面这份可以直接作为V1.0建库基础。

```sql
CREATE TABLE meeting_room (
    id BIGSERIAL PRIMARY KEY,
    room_code VARCHAR(50) NOT NULL UNIQUE,
    room_name VARCHAR(100) NOT NULL,
    building VARCHAR(100),
    floor VARCHAR(50),
    location_desc VARCHAR(255),
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    inspection_enabled BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE inspection_indicator (
    id BIGSERIAL PRIMARY KEY,
    indicator_code VARCHAR(50) NOT NULL UNIQUE,
    indicator_name VARCHAR(100) NOT NULL,
    category VARCHAR(50) NOT NULL,
    description TEXT,
    normal_condition TEXT NOT NULL,
    abnormal_condition TEXT NOT NULL,
    ai_supported BOOLEAN NOT NULL DEFAULT TRUE,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    sort_order INT DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE standard_photo (
    id BIGSERIAL PRIMARY KEY,
    room_id BIGINT NOT NULL REFERENCES meeting_room(id),
    photo_type VARCHAR(20) NOT NULL,
    photo_url TEXT NOT NULL,
    photo_hash VARCHAR(128),
    shoot_position VARCHAR(100),
    camera_direction VARCHAR(100),
    version INT NOT NULL DEFAULT 1,
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(room_id, photo_type, version)
);

CREATE TABLE photo_region (
    id BIGSERIAL PRIMARY KEY,
    standard_photo_id BIGINT NOT NULL REFERENCES standard_photo(id),
    region_code VARCHAR(50) NOT NULL,
    region_name VARCHAR(100) NOT NULL,
    x DECIMAL(8,6) NOT NULL,
    y DECIMAL(8,6) NOT NULL,
    width DECIMAL(8,6) NOT NULL,
    height DECIMAL(8,6) NOT NULL,
    description TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE room_indicator (
    id BIGSERIAL PRIMARY KEY,
    room_id BIGINT NOT NULL REFERENCES meeting_room(id),
    indicator_id BIGINT NOT NULL REFERENCES inspection_indicator(id),
    standard_value VARCHAR(100),
    region_id BIGINT REFERENCES photo_region(id),
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    sort_order INT DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(room_id, indicator_id)
);

CREATE TABLE inspection_task (
    id BIGSERIAL PRIMARY KEY,
    task_no VARCHAR(50) NOT NULL UNIQUE,
    room_id BIGINT NOT NULL REFERENCES meeting_room(id),
    inspection_date DATE NOT NULL,
    period VARCHAR(20) NOT NULL,
    inspector_id BIGINT,
    status VARCHAR(30) NOT NULL DEFAULT 'PENDING',
    due_at TIMESTAMP,
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(room_id, inspection_date, period)
);

CREATE TABLE inspection_photo (
    id BIGSERIAL PRIMARY KEY,
    task_id BIGINT NOT NULL REFERENCES inspection_task(id),
    photo_type VARCHAR(20) NOT NULL,
    photo_url TEXT NOT NULL,
    original_filename VARCHAR(255),
    width INT,
    height INT,
    file_size BIGINT,
    quality_status VARCHAR(20),
    quality_reason TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(task_id, photo_type)
);

CREATE TABLE inspection_result (
    id BIGSERIAL PRIMARY KEY,
    task_id BIGINT NOT NULL REFERENCES inspection_task(id),
    indicator_id BIGINT NOT NULL REFERENCES inspection_indicator(id),

    ai_status VARCHAR(20),
    ai_confidence DECIMAL(5,4),
    ai_reason TEXT,
    ai_bbox JSONB,

    human_status VARCHAR(20),
    human_remark TEXT,

    final_status VARCHAR(20),

    confirmed_by BIGINT,
    confirmed_at TIMESTAMP,

    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE(task_id, indicator_id)
);
```

# 25. 这里还有一个重要设计：不要把AI Prompt存死在代码里

```text
ai_inspection_rule
```

如果写死在Python代码：

```python
prompt = "......"
```

每次都要改代码。

如果放数据库：

```text
AI规则V1
 ↓
AI规则V2
 ↓
```

就可以管理。
